## 5. Nix packaging

**The supported mechanism is a setup hook, not a builder.** nixpkgs ships `cargo-tauri` (`pname = "tauri"`, version 2.11.4 on master), whose `passthru` exposes exactly two things: `hook` and `gst-plugin` ([package.nix](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/ca/cargo-tauri/package.nix)). The hook is documented in `doc/hooks/tauri.section.md`, rendered at [nixos.org/manual/nixpkgs/unstable/#tauri-hook](https://nixos.org/manual/nixpkgs/unstable/#tauri-hook). That file exists on `release-25.05`, `release-25.11` and `master` alike (all HTTP 200), so the hook is available in both current stable channels.

**Explicitly a myth: there is no `tauriBundle` / `buildTauriApp` in nixpkgs.** `pkgs/top-level/all-packages.nix` on master contains **zero** occurrences of "tauri" — by-name packages are auto-called, and the only Tauri-specific helper anywhere in nixpkgs is `cargo-tauri.hook`. `doc/languages-frameworks/rust.section.md` never mentions Tauri; `pkgs/build-support/rust/` has no Tauri hook. `buildTauriApp` **does** exist, but in the third-party flake [JPHutchins/crane-tauri](https://raw.githubusercontent.com/JPHutchins/crane-tauri/main/README.md), which is not nixpkgs and not official — do not describe it as a nixpkgs helper.

**What the hook actually does** ([hook.nix](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/ca/cargo-tauri/hook.nix), [hook.sh](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/ca/cargo-tauri/hook.sh)): it sets `dontCargoBuild=true` / `dontCargoInstall=true` (replacing `cargoBuildHook`/`cargoInstallHook`) and assigns `buildPhase=tauriBuildHook`, `installPhase=tauriInstallHook`, plus `tauriFixupHook` into `preFixupPhases`. It invokes `cargo tauri build --bundles <type> --target <spec> -- <cargo args>` with cargo args `-j $NIX_BUILD_CORES --target <spec> --offline`; because Tauri ignores `CARGO_TARGET_DIR` ([tauri#10190](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/ca/cargo-tauri/hook.sh)) it appends `build.target-dir` to `config.toml`. Bundle type defaults are `darwin = "app"; linux = "deb";` and the Darwin install script moves `bundle/macos/*.app` into `$out/Applications`. Linux fixup adds `WEBKIT_GST_ALLOWED_URI_PROTOCOLS=asset`, a gstreamer plugin path, and `__NV_DISABLE_EXPLICIT_SYNC=1` (for [tauri#9394](https://v2.tauri.app/develop/debug/linux-graphics/)). Tunables: `tauriBuildFlags`, `tauriBundleType`, `dontTauriBuild`, `dontTauriFixup`, `dontTauriInstall`, plus honored `buildAndTestSubdir`, `cargoBuildType`, `cargoBuildNoDefaultFeatures`, `cargoBuildFeatures`.

**Real, currently-existing expression** — [`cc-switch`](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/cc/cc-switch/package.nix) uses the hook with pnpm:

```nix
pnpmDeps = fetchPnpmDeps { inherit (finalAttrs) pname version src; pnpm = pnpm_10; fetcherVersion = 3; hash = "..."; };
cargoRoot = "src-tauri";
buildAndTestSubdir = finalAttrs.cargoRoot;
nativeBuildInputs = [ cargo-tauri.hook jq moreutils nodejs pnpmConfigHook pnpm_10 ]
  ++ lib.optionals stdenv.hostPlatform.isLinux [ pkg-config wrapGAppsHook3 ];
buildInputs = lib.optionals stdenv.hostPlatform.isLinux [
  glib-networking libayatana-appindicator libsoup_3 openssl webkitgtk_4_1
];
```

[`deltachat-tauri`](https://raw.githubusercontent.com/NixOS/nixpkgs/master/pkgs/by-name/de/deltachat-tauri/package.nix) is the Darwin counterpart: `apple-sdk_14` in `buildInputs`, `darwin.autoSignDarwinBinariesHook` in `nativeBuildInputs`, `fetcherVersion = 4`.

**pnpm attribute names are version-critical.** Current attrs are underscore-form — `pnpm_9`, `pnpm_10`, `pnpm_10_29_2`, `pnpm_11` (`pnpm = pnpm_11` on master); `pnpm-10` is *not* an attribute (zero `pnpm-[0-9]` matches in `all-packages.nix`). More importantly, **`fetchPnpmDeps` and `pnpmConfigHook` do not exist in nixpkgs 25.05**: the [25.05 JS manual](https://raw.githubusercontent.com/NixOS/nixpkgs/release-25.05/doc/languages-frameworks/javascript.section.md) documents only the old per-package API `pnpm_9.fetchDeps` / `pnpm_9.configHook` (and only lists `pnpm_8`/`pnpm_9`), whereas [25.11](https://raw.githubusercontent.com/NixOS/nixpkgs/release-25.11/doc/languages-frameworks/javascript.section.md) and [master](https://raw.githubusercontent.com/NixOS/nixpkgs/master/doc/languages-frameworks/javascript.section.md) document `fetchPnpmDeps`/`pnpmDeps`/`pnpmConfigHook` with `fetcherVersion = 4`. The manual's own Tauri example uses **npm** (`fetchNpmDeps`, `npmHooks.npmConfigHook`), not pnpm. Note `fetchPnpmDeps`'s `fetcherVersion` differs between real packages (3 in cc-switch, 4 in deltachat-tauri) — it tracks the fetcher implementation, so copy the value from the branch you target.

**The frontend-in-sandbox problem is real and documented in code.** `cargo tauri build` runs `beforeBuildCommand` via `helpers::run_hook("beforeBuildCommand", ...)` ([build.rs](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-cli/src/build.rs)), which would attempt `pnpm install` with no network. Separately, `frontendDist` must exist *before* the Rust compile: tauri-codegen panics ``The `frontendDist` configuration is set to `{path:?}` but this path doesn't exist`` ([context.rs](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-codegen/src/context.rs)), and the CLI bails with `Unable to find your web assets, did you forget to build your web app?`. The hook does **not** neutralise either; packagers do it manually. cc-switch's comment states it plainly: *"tauri-build embeds frontendDist (../dist) at compile time; populate it before cargo tauri build runs (beforeBuildCommand is stripped in postPatch)"* — it strips the command with `jq 'del(.build.beforeBuildCommand) | ...' src-tauri/tauri.conf.json | sponge` and then runs `preBuild = '' pnpm run build:renderer ''`. The clean alternative is the `--config` override: `build.rs` declares `pub config: Vec<ConfigValue>`, and [helpers/config.rs](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-cli/src/helpers/config.rs) merges it and does `set_var("TAURI_CONFIG", merge_config_str)`, which [tauri-build](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-build/src/lib.rs) reads back — crane-tauri exposes exactly this as `configFlag`/`tauriConfig` and passes a pre-built frontend derivation into `frontendDist`.

**Corrections to commonly-repeated claims.** `TAURI_SKIP_DEVSERVER_CHECK` is **obsolete** — the CLI CHANGELOG records it renamed to `TAURI_CLI_NO_DEV_SERVER_WAIT` ([ENVIRONMENT_VARIABLES.md](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-cli/ENVIRONMENT_VARIABLES.md), [CHANGELOG.md](https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-cli/CHANGELOG.md)), and it only concerns dev-server waiting, not `build`. Version-mismatch failures are routine: build.rs calls `check_mismatched_packages` and errors unless `--ignore-version-mismatches` is passed (cc-switch sets `tauriBuildFlags = [ "--ignore-version-mismatches" ];`); `deltachat-tauri` is currently `broken = true; # Error Found version mismatched Tauri packages.`

**Darwin.** `apple-sdk_14` is the current attribute; master defines `apple-sdk_14/15/26` and `darwin-packages.nix` only references the `apple-sdk` name, with no `darwin.apple_sdk.frameworks` entries. **I could not verify the deprecation from release notes** — grepping `rl-2411.section.md` and `rl-2505.section.md` for `apple.?sdk` returned nothing; the evidence is the current attribute set plus real expressions. On bundling, nixpkgs deliberately avoids DMG: the hook defaults to `app`, PR [#499908](https://github.com/NixOS/nixpkgs/pull/499908.diff) restricted install to `*.app` only, and cargo-tauri carries `skip-icon-macos.patch` ([PR #490155](https://github.com/NixOS/nixpkgs/pull/490155.diff)) deleting the `SetFile -c icnC` / `SetFile -a C` calls from Tauri's `bundle/macos/dmg/bundle_dmg`. **I found no source confirming an `hdiutil`-unavailable-in-sandbox failure specifically** — flag this as unverified; what is verified is that the DMG script depends on `hdiutil` and `SetFile` and that nixpkgs patched it and defaults away from `dmg`. `MACOSX_DEPLOYMENT_TARGET` and `GDK_BACKEND`: **not verified anywhere** in the sources I fetched. cc-switch shows an unrelated sandbox limit: a test is skipped because *"Proxy startup test binds to a local address, which the darwin sandbox blocks."*

**Linux inputs** (Tauri's [prerequisites](https://v2.tauri.app/start/prerequisites/) plus the expressions above): `webkitgtk_4_1`, `libsoup_3`, `glib-networking`, `libayatana-appindicator`, `openssl`, `pkg-config`, `wrapGAppsHook3`/`wrapGAppsHook4`, optional `gst_all_1.*`. Tauri's Debian list includes `libxdo-dev`, but **no nixpkgs expression I read needs `xdotool`** — treat that as unverified. Both apps patch appindicator's hardcoded `dlopen`: `substituteInPlace $cargoDepsCopy/*/libappindicator-sys-*/src/lib.rs --replace-fail "libayatana-appindicator3.so.1" "${libayatana-appindicator}/lib/libayatana-appindicator3.so.1"`. Rendering bugs persist — [#539384](https://github.com/NixOS/nixpkgs/issues/539384) "webkitgtk_4_1: Tauri app renders incorrectly" is open.

**Community helpers.** [dream2nix](https://github.com/nix-community/dream2nix) has **no Tauri support**: a full tarball of `main` (298 `.nix` files, with rust and nodejs modules present) contains zero case-insensitive "tauri" matches. Beyond crane-tauri, I did not verify Tauri-specific handling in crane, naersk or fenix themselves. The official NixOS Wiki [Tauri](https://wiki.nixos.org/wiki/Tauri) page defers to the nixpkgs manual and adds only a `nix-shell` dev-shell snippet and a pointer to crane-tauri; its `nix-shell` example lists `webkitgtk_4_1` and `librsvg` and exports `XDG_DATA_DIRS="$GSETTINGS_SCHEMAS_PATH"`. Tauri's own docs point Nix users at that wiki page rather than documenting Nix packaging itself.

**Bottom line:** use `cargo-tauri.hook`; there is no `tauriBundle`; expect to strip `beforeBuildCommand` (or inject `frontendDist` via `--config`/`TAURI_CONFIG`), pin `pnpmConfigHook` per nixpkgs release, and expect `app`-only Darwin bundles.
